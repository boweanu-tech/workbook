# 注意点

- texを生成する時必ずコンパイルが通るものを生成すること。
- .sty内のコマンドは不用意に消さないこと
	- 他のバリアント等で使う場合があるため
- gitの999_GPTboxフォルダに必要な.styなどは入れていきます。
- 全体に波及するべきレイアウト調整は、.styで行ってください。
- .styのコマンド・命令を消す場合、互換性を考えてください。
	- 過去に作ったtexファイルもコンパイルが通るようにすること。
- 数値替えの小問を並べるとき、例えば「簡単な順番」や「数が小さい順」など、単調に並ばないようにすること。
- 問題の分類が数学的な単元の分類と一致している必要はない。
	- むしろあえて混ぜることで、最適な方法を選択する判断力を養ってもらうことが大切。
- 不等号について、\leqや\geqではなく、\leqqや\geqqを使うこと。
- 図形の頂点や動点などのアルファベットは、斜体ではなく{\rm}を用いる。三角形などはlotusmath.styにコマンドがある。
	- .svgの図中も同様、斜体にはせずローマン体にする。
	- 指定法：font-family: "CMU Serif", "Computer Modern Serif", "Latin Modern Roman", "Times New Roman", serif;  font-style: normal;

# テーマや単元・内容について
- 内容の階層構造は
	- 「学年」→「単元」→「テーマ」
- テーマはバリアイント(test_やlesson_)が変わっても変更しない。
- バリアントを跨いで同じ問題があってもいいが、原則は数値替え・聞き方をほんの少し変えるなど工夫を。

# 問題取り込みについて

- pdfや画像などの外部資料から問題を生成することを「取り込む」と言います。
 - 著作権に配慮する
	- 外部資料から、出題すべき知識・技能・用語・典型処理・問題のポイント・狙いを抽出する。  
	- 問題文・解説文・図・表・配列は流用しない。  
	- 自塾の形式・粒度・順序に合わせて再構成する。
	-  外部資料の文を穴抜き化しない。  
	- 数字や固有名詞だけを変えた改変問題は作らない。  
	- 図は元資料をトレースせず、同じ概念を説明するための別構成の図として作る。  
	- 生成後、元資料と見比べて「表現上の本質的特徴」が残っていないか確認する。



# 環境について

## ディレクトリとファイル名
- ディレクトリ：「科目フォルダ/学年＋単元名フォルダ」
	- 例)「001_math/23_2_roots」
	- 中学の副教科等には学年がない場合もある
- ファイル：「ページタイプ＋2ケタゼロ埋め自然数.tex」
	- 例)「test_02.tex」
- 通し番号については、「進捗」mdファイルを参照
- .svgと.pdfは、その単元フォルダの直下のfig/に保管
	- .svg内のコメントは遵守する
	- .svgを生成する際は、以下のファイルを雛形として作成する
	- .pdfは生成しない(ローカルで自動生成)
	-  999_GPTbox/template.svg
	-  999_GPTbox/temp_graph.svg
